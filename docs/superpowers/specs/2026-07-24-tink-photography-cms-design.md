# Tink Photography 动态内容与管理后台设计

日期：2026-07-24

## 目标

以 `tink-photography-main.zip` 中的 Astro 7 项目为访客端基线，完整保留现有页面结构、视觉样式、响应式布局、明暗主题和动画体验，并新增可部署在单台 VPS 上的内容管理后台。

后台支持单管理员维护三级摄影内容结构“分类 → 图集 → 图片”，同时管理博客、关于页和站点资料。图片既可上传到服务器，也可直接使用外部 HTTPS 链接。

## 范围

### 访客端

- 保留原项目首页、主题目录、图集详情、博客、关于页和 404 页。
- 保留 Astro 组件、SCSS、GSAP、Lenis、Swiper、预加载、光标及明暗主题交互。
- 将当前写死在 TypeScript、Astro 和 Markdown 文件中的可编辑内容迁移到数据库。
- 保留全部现有公开 URL；旧分类页和特辑页通过兼容路由映射到迁移后的同名首个图集，已有链接不得失效。
- 前台只显示已发布内容；管理员可在后台预览草稿。

### 管理后台

- 单管理员登录、退出和受保护会话。
- 仪表盘展示分类、图集、图片与文章数量、最近更新和异常外链提示。
- 分类、图集、图片、博客、关于页和站点资料管理。
- 后台采用高信息密度的左侧导航工作台，视觉克制，并适度继承 Tink 的黑白字体风格。
- 后台同时支持桌面和移动设备，但批量排序与编辑优先优化桌面操作。

## 技术架构

项目升级为 Astro SSR 单体应用，由一个 Node 服务同时提供访客站、`/admin` 后台和服务端写操作。部署目标为 Docker Compose 管理的单台 VPS。

- Web：Astro 7 SSR 与 Node adapter。
- 数据库：SQLite，使用 WAL 模式和持久化 Docker 卷。
- 数据访问：类型安全的 repository/service 边界；页面与后台操作不直接拼接 SQL。
- 图片处理：Sharp。
- 文件存储：原图和派生图片放在独立持久化卷。
- 登录：环境变量提供初始管理员用户名和密码，数据库只保存安全密码哈希或受保护的初始化状态。
- 会话：HTTP-only、Secure、SameSite Cookie；生产环境仅允许 HTTPS。

访客页面沿用现有 Astro 组件。组件通过统一查询层获得数据，避免将数据库访问分散到页面模板中。后台表单通过服务端 action/API 调用领域服务，所有写操作进行身份校验、输入校验和必要的数据库事务处理。

## 数据模型

### Category

- `id`
- 中文标题、英文标题
- 唯一 `slug`
- 描述、封面
- 排序值
- 草稿/发布状态
- 创建和更新时间

### Album

- `id`、`categoryId`
- 中文标题、英文标题
- 唯一 `slug`
- 描述、日期、地点、标签
- SEO 标题、描述和关键词
- 封面图片引用
- 首页精选状态与排序
- 草稿/发布状态
- 创建和更新时间

### Photo

- `id`、`albumId`
- 来源类型：`upload` 或 `external`
- 原图路径或外链 URL
- AVIF/WebP 响应式派生文件路径
- 缩略图路径
- 替代文本、宽度、高度
- 排序值
- 自动版式结果与可选的人工版式覆盖
- 创建和更新时间

### Post

- `id`、标题、`slug`
- Markdown 正文、摘要、封面
- SEO 字段
- 草稿/发布状态与发布时间
- 创建和更新时间

### AboutPage

- 姓名、身份说明、简介和详细介绍
- 头像/主图，可使用上传图片或外链
- 邮箱
- 可排序的个人资料条目
- 可排序的社交链接
- SEO 字段

### SiteSettings

- 站名、短名称和默认域名
- 首页标题、介绍和其他可编辑文案
- 默认 SEO
- 统计代码配置

## 后台功能

### 分类管理

管理员可新增、编辑、发布、隐藏和拖拽排序分类，并设置分类封面。分类下存在图集时禁止直接删除，界面说明冲突原因。

### 图集管理

管理员选择所属分类，维护标题、描述、日期、地点、标签、SEO、封面、首页精选和发布状态。图集支持排序与预览。

### 图片库

- 批量上传本地图片。
- 添加一个或多个 `http/https` 外链。
- 拖拽排序、批量删除、替换、编辑替代文本和设置封面。
- 根据图片横竖比例自动选择原项目风格的版式。
- 允许人工切换宽幅、标准、窄幅、左/中/右对齐和背景留白等预设。

本地上传图片保留原图，并生成缩略图及响应式 AVIF/WebP。外链由访客浏览器直接加载，不由服务端下载或转码。后台在浏览器侧检查加载结果并标记异常链接。

### 博客管理

提供 Markdown 编辑器和实时预览，维护标题、slug、正文、摘要、封面、SEO、草稿/发布状态和发布时间。

### 关于页管理

独立管理头像/主图、姓名、身份说明、简介、详细介绍、邮箱、个人资料条目、社交链接和 SEO。资料条目与社交链接支持新增、删除及排序。

### 站点设置

管理站名、首页文案、默认 SEO、域名与统计代码。关于页内容不混入通用设置。

## 图片写入流程

1. 服务端校验管理员会话、文件数量、MIME 类型、扩展名和大小。
2. 文件写入上传卷内的临时目录。
3. Sharp 读取尺寸并生成缩略图和响应式 AVIF/WebP。
4. 派生文件全部成功后，原子移动到正式目录并在数据库事务中创建记录。
5. 任何步骤失败时清理本次临时文件，不留下半完成数据。

删除本地图片时，同时清理其派生文件。删除外链图片只删除数据库记录。替换图片成功后再移除旧文件，避免失败时丢失当前内容。

## 安全与错误处理

- 所有 `/admin` 页面和写接口必须验证登录会话。
- 密码使用适合生产环境的强哈希算法；不记录明文密码。
- 登录接口限流，并使用通用错误文案避免泄露账号是否存在。
- 所有表单执行服务端 schema 校验，并显示字段级错误且保留已填写内容。
- slug 在数据库层保证唯一；冲突时给出可操作提示。
- 上传限制允许的图片类型、文件大小和单次数量。
- Markdown 输出经过安全处理，防止脚本注入。
- 外链仅接受合法 `http/https` URL；服务端不主动请求外链，避免 SSRF。
- 删除操作二次确认；有依赖关系的内容禁止直接删除。
- 磁盘不足、处理失败和数据库错误返回明确但不泄露内部路径的提示。
- 前台图片失败时显示不破坏布局的占位状态。

## 数据迁移

导入压缩包中的全部现有资源和内容：

- 原有每个摄影分类迁移为一个 Category。
- 在每个 Category 下创建一个同名的初始 Album，并导入对应照片和版式配置。
- 首页精选卡片迁移为可排序的精选图集/图片引用。
- 现有 Markdown 博客迁移为 Post。
- `site.ts`、首页和关于页中的可编辑文案迁移到 SiteSettings 与 AboutPage。
- 保留无法直接归一化的展示字段，确保迁移后的首屏内容和旧站一致。

迁移脚本必须幂等或显式拒绝重复运行，避免重复导入内容。

## 测试与验收

### 自动化测试

- 数据库 schema、迁移、查询和排序测试。
- 登录、退出、会话过期、限流和未授权访问测试。
- 分类、图集、图片、博客、关于页和站点设置 CRUD 集成测试。
- 上传成功、类型/大小拒绝、处理失败回滚和文件清理测试。
- 外链 URL 校验与异常显示测试。
- 旧 URL 兼容和草稿隔离测试。
- Playwright 覆盖管理员核心流程及桌面/移动访客页面。

### 验收标准

- 原项目访客端的页面结构、样式、主要动画和明暗主题无明显视觉回归。
- 初始数据库包含原项目现有内容，原有照片与页面均可访问。
- 管理员可以登录，并完整管理分类、图集、图片、博客、关于页和站点资料。
- 本地图片上传后生成优化格式，发布后立即出现在访客端。
- 外链图片无需下载即可加入图集，并在加载失败时获得明确提示。
- 分类、图集和图片排序会稳定反映到访客端。
- 未登录用户无法访问后台内容或执行写操作。
- `docker compose up` 可在配置环境变量和持久化目录后启动完整应用。

## 非目标

- 多管理员、角色与权限系统。
- 云对象存储或 CDN 的首版集成。
- 自动将外链图片下载到本地。
- 在线图片修图、裁剪或水印编辑器。
- 前台评论、会员、付费或社交功能。
- 将后台视觉完全复刻为访客端的艺术化画廊布局。
