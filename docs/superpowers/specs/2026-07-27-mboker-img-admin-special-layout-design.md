# Mboker Img 后台与特辑区块排版设计

日期：2026-07-27

## 背景

当前项目已经将原 Tink 摄影站改造成数据库驱动的 Astro SSR 应用，并具备分类、图集、图片、博客、关于页和站点设置后台。此次迭代不改变普通访客页面的视觉语言，重点解决四个问题：

1. 后台工作台需要更现代、清晰，且不增加搜索功能。
2. 博客文章保存、预览、发布和撤回流程需要更直接。
3. 图集图片布局需要更易理解和预览。
4. 数据库版没有还原原站“阿勒泰”特辑的分栏效果，需要支持图片与 Markdown 文字自由组合排版。

原版视觉参考为 <https://tinks.netlify.app/posts/altay/>。桌面端以图片和文字分栏为主，移动端依次显示标题、文字和图片。

## 目标

- 将所有用户可见的 Tink 品牌替换为 `Mboker Img`。
- 保持原项目前台的页面结构、留白、字体、主题和动画语言。
- 后台采用深绿色侧栏、白色工作区和克制的现代圆角矩形设计。
- 提供受控的 WordPress 风格特辑区块编辑器，而不是完整 Gutenberg 编辑器。
- 支持任意长度 Markdown，并与上传图片、外链图片共同排版。
- 优化博客草稿、预览、发布、定时发布和撤回工作流。
- 修复自定义鼠标脚本失败后系统鼠标也被隐藏的问题。
- 保留现有数据库内容，并恢复阿勒泰的原始特辑效果。

## 非目标

- 不增加任何搜索框、全文搜索或搜索接口。
- 不实现任意嵌套区块、插件系统、自由拖拽列宽或完整所见即所得编辑器。
- 不重新设计普通图集、首页、关于页或博客访客页面。
- 不增加多管理员、角色权限、评论、会员或云对象存储。
- 不把 Docker 持久化数据或备份迁移到 C 盘。

## 视觉方向

后台使用已确认的“安静工作室”方向：

- 桌面端使用深绿色固定侧栏和白色主工作区。
- 面板圆角约 `8px`，按钮、输入框和状态标签圆角约 `6px`。
- 状态、提示和危险操作使用清晰的中性色、绿色、琥珀色和红色，不使用单一色相铺满页面。
- 页面以表格、表单分区和工具栏为主，不堆叠装饰卡片。
- 图标按钮使用现有 Lucide 图标并提供工具提示。
- 移动端侧栏收为抽屉，表单和编辑区转为单列。

## 特辑内容模型

### Album 扩展

在 `albums` 表增加：

- `isSpecial`: 布尔值，默认 `false`。
- `specialLayoutJson`: 版本化 JSON，默认 `{ "version": 1, "blocks": [] }`。

普通图集忽略 `specialLayoutJson`，继续使用现有动态图片画廊。特辑图集仅按照区块列表渲染；未被任何区块引用的图集图片仍保留在图片库中，但不出现在特辑前台。

### 区块结构

`specialLayoutJson.blocks` 是有序数组。每个区块包含稳定客户端 ID 和以下类型之一：

- `image`: 单张通栏图片。
- `markdown`: 单个通栏 Markdown 长文。
- `split`: 图片与 Markdown 分栏，通过 `direction` 表示左图右文或左文右图。
- `twoImages`: 两张图片并排。

分栏和双图区块支持 `1:1`、`2:3`、`3:2` 比例。分栏区块支持顶部、居中和底部垂直对齐。区块引用图片 ID，不复制图片 URL、替代文本或派生图信息；图片上传、替换、外链来源和替代文本继续由现有图片库统一管理。

Markdown 沿用现有 `marked` 与 `sanitize-html` 服务，只允许安全的标题、段落、列表、链接、引用、代码、强调和图片等元素。禁止脚本、事件属性、`javascript:` URL 和未授权 HTML。

### 删除与缺失引用

删除正在被特辑区块引用的图片时，确认对话框必须列出引用数量。确认删除后不阻止操作：

- 后台相应区块显示“图片已缺失”，并允许重新选择图片或删除区块。
- 访客端跳过纯图片区块；分栏区块若只剩 Markdown，则以通栏 Markdown 显示；双图区块若只剩一张图片，则以单图显示。
- 保存特辑时允许缺失引用存在，但必须给出非阻塞警告。

## 特辑后台编辑器

图集编辑页组织为“基本信息、图片管理、特辑排版”三个页签。只有打开“设为特辑”后才启用特辑排版页。

编辑器顶部包含：

- 返回图集列表。
- 当前保存状态。
- 桌面端和移动端预览切换。
- 保存按钮和前台预览入口。

编辑区提供五个用户操作入口：通栏图片、通栏文字、左图右文、左文右图、双图。内部数据的两种分栏方向都使用 `split` 类型。

每个区块使用独立圆角面板：

- 可通过拖动手柄排序。
- 同时提供上移和下移按钮，保证键盘与触屏可用。
- 可删除区块，删除前显示目标名称。
- 图片区域打开当前图集的图片选择器。
- 图片选择器内可直接进入上传或外链添加流程；新图片创建成功后自动选中。
- Markdown 提供编辑与预览切换，长文编辑区具有稳定高度，可继续扩展。
- 分栏区块提供比例和垂直对齐选项。

保存采用现有受保护 API，不刷新整页。编辑器显示“未保存、保存中、已保存、保存失败”状态。保存失败时保留全部区块和 Markdown。存在未保存改动时关闭或离开页面，需要浏览器确认。

## 特辑访客渲染

新增独立的特辑渲染组件，由访客图集查询返回已校验的区块和对应图片。

- 桌面端按后台区块顺序渲染，保持原站的大留白和图像比例。
- 首个左图右文区块可以复刻阿勒泰首屏。
- 现有图片的 `layoutPreset`、背景、内边距、对齐、响应式派生图和替代文本继续生效；区块比例负责外层分栏。
- 本地上传图片使用 AVIF/WebP 响应式资源，外链图片直接使用原 HTTPS 地址。
- 图片容器使用已知宽高或稳定比例，加载失败时保留版面，不产生大幅跳动。
- 移动端所有区块按视觉顺序转为单栏：左侧内容在前、右侧内容在后。
- 页面标题、导航、主题切换、下一篇和页脚继续沿用原项目前台组件。

## 阿勒泰兼容迁移

迁移和旧内容导入必须幂等。对于 `slug = altay` 且尚无特辑区块的现有图集：

1. 设置 `isSpecial = true`。
2. 按现有图片顺序查找原始 17 张图片。
3. 首张图片与原 `PostInfo.astro` 行程资料生成一个左图右文区块。
4. 其余图片生成通栏图片区块，并保留当前窄幅、背景、留白和对齐设置。
5. 保留 `/posts/altay` 到当前图集 URL 的兼容路径。

初始 Markdown 包含原行程、英文名、地理位置、记录时间、印象、体验推荐和路线参考。迁移只在特辑版式为空时执行，不覆盖管理员后来保存的内容。

## 图片管理工作流

现有图片库继续支持上传、外链、替换、编辑、删除和排序，并做以下优化：

- 图片设置保存后局部更新缩略图和状态，不整页刷新。
- 宽幅、标准、窄幅使用分段控件；对齐使用图标或明确的选项控件。
- 设置区实时预览背景、留白和宽度效果。
- 允许将当前布局设置批量应用到已选图片。
- 删除和替换操作明确说明是否影响特辑区块。
- 外链只接受合法 `http/https` 地址，不由服务端抓取或转存。

## 博客发布工作流

文章列表不提供搜索，只提供“全部、草稿、已发布”状态页签和新建按钮。列表使用紧凑表格，显示标题、状态、发布时间和最后修改时间。

文章编辑页顶部固定发布工具栏：

- 左侧显示返回、文章状态和未保存提示。
- 草稿提供“保存草稿、预览、发布”。
- 已发布文章提供“更新、预览、撤回为草稿”。
- 预览使用受管理员会话保护的真实前台渲染，并在新标签页打开，不要求先发布。
- 发布时可以设置时间；未来时间到达前，公开查询不返回该文章。
- 保存、发布或撤回失败时保留标题、摘要、封面、SEO 和 Markdown 内容。
- 离开未保存文章时进行确认。

文章字段继续使用当前标题、slug、摘要、封面、Markdown、SEO、状态和发布时间，不引入新的内容模型。

## 品牌替换

将用户可见的 `Tink`、`Tink.` 和 `Tink Photo Gallery` 替换为 `Mboker Img`，范围包括：

- 访客端导航、页脚、页面标题、默认 SEO、关于页默认资料和可见文案。
- 后台登录页、侧栏、标题和提示。
- 导入脚本的新安装默认值。
- `package.json` 项目名、README 标题和 Docker Compose 服务/容器显示名称。

SQLite 文件路径和既有 Docker 数据目录保持兼容，避免为了品牌名迁移而移动或丢失数据。原作者链接只有在当前页面仍作为内容展示时保留，不再作为本站品牌标识。

## 自定义鼠标修复

当前 `Cursor.astro` 依赖 Paper.js，而生产 CSP 禁止其使用 `unsafe-eval`。脚本初始化失败后，CSS 仍无条件设置 `cursor: none`，导致系统鼠标消失。

修复方案：

- 移除 Paper.js 光标实现及依赖。
- 使用原生 `pointermove` 和 `requestAnimationFrame` 更新圆形光标位置。
- 默认保留系统鼠标；只有自定义光标元素、脚本和指针能力全部初始化成功后，才添加隐藏系统鼠标的根级类。
- 脚本异常、触屏设备或 `prefers-reduced-motion` 模式下不添加该类。
- 页面卸载时移除事件和动画帧。

## API、校验与错误处理

- 所有特辑写接口复用现有管理员会话校验。
- 特辑 JSON 使用 Zod 判别联合校验，限制区块数量、Markdown 字符数、合法比例、合法方向和正整数图片 ID。
- 服务器验证引用图片属于当前图集，禁止跨图集引用。
- 版式保存和相应图集更新时间在同一事务内完成。
- API 使用现有错误响应格式，区分未授权、找不到图集、无效字段、图片归属冲突和数据库失败。
- 客户端错误提示使用中文，不暴露数据库路径、堆栈或部署目录。

## 关键验证

用户要求缩短质量审查，因此只保留与本次改动直接相关的发布门槛：

1. 运行 Astro 类型检查和生产构建。
2. 对特辑 schema、图片归属、缺失图片降级和未来发布时间查询执行集中测试。
3. 使用真实浏览器跑通登录、保存草稿、预览、发布、撤回、创建特辑、添加五类区块、排序、上传图片、添加外链、替换和删除图片。
4. 对阿勒泰桌面端和移动端截图检查分栏、单栏降级、文字溢出、图片加载和系统鼠标可见性。
5. 使用 Docker Compose 启动实际容器并访问关键页面；数据库、上传和备份继续挂载在 D 盘目录。

验收条件：

- 普通图集无明显视觉回归。
- 阿勒泰重新呈现原站的特辑分栏效果，且可在后台继续编辑。
- 管理员可以用五类区块编排任意长度 Markdown 与图集图片。
- 文章无需发布即可预览，并可正常发布、定时显示和撤回。
- 图片上传、外链、替换、删除和原有布局修改均可用。
- 前台系统鼠标不再因自定义脚本失败而消失。
- 后台没有搜索选项，并符合已确认的深绿色、白色和现代圆角方向。
- 所有可见品牌为 `Mboker Img`。
- Docker 持久数据和备份不写入 C 盘。

## 交付
